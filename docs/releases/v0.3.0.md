# v0.3.0 — Native Agent Adapters

Release date: 2026-08-08

## Highlights

`v0.3.0` upgrades `airules` from mostly thin agent entrypoints to agent-native rule delivery while preserving one canonical engineering rule catalog.

### Native Cursor rules

Cursor now receives thematic `.cursor/rules/airules-*.mdc` files. The old airules-owned `.cursor/rules/engineering.mdc` adapter is migrated safely. Generated Cursor rules no longer depend on `@../../.ai-rules/...` references.

### Native Claude Code rules

Claude Code now receives `.claude/rules/airules/*.md` and keeps a short root `CLAUDE.md` entrypoint for project-specific instructions.

### GitHub Copilot support

`copilot` is a first-class `--ide` target. Projects receive `.github/copilot-instructions.md` and thematic `.github/instructions/airules/*.instructions.md` files.

### Codex remains intentionally compact

Codex keeps a short `AGENTS.md` index and reads the generated effective snapshot plus project-specific instructions. This avoids inflating automatically loaded Codex instruction context.

### Safer adapter lifecycle

`sync` can remove stale generated native rule files only when they contain an airules ownership marker. Unrelated project-authored instruction files remain untouched.

## Supported agents

- OpenAI Codex
- Claude Code
- Cursor
- GitHub Copilot
- Gemini CLI

## Upgrade

From an existing Git install:

```bash
uv tool upgrade ai-engineering-rules
```

After upgrading, run in each attached project:

```bash
airules sync
airules doctor
```

For Cursor projects previously using the old `engineering.mdc` adapter, `sync` migrates only the airules-owned file.

## Compatibility

- Existing manifests without `ides` continue to mean all supported adapters.
- Persisted `ides` selections remain valid.
- `.ai-rules/project.md` remains user-owned and is never overwritten by `sync`.
- `.ai-rules/generated.md` remains the complete effective-rule snapshot.

## Validation performed for this release candidate

- full source test suite: 90 tests passed;
- `compileall` passed;
- CLI version/help smoke passed;
- installed-wheel smoke passed for Cursor, Claude Code, Codex, and GitHub Copilot;
- installed package contained 82 canonical rules and 6 profiles;
- generated/stale adapter ownership behavior was covered by regression tests.

The sandbox package registry used during development did not provide `hatchling`, so the normal `uv build` backend path could not be exercised there. An equivalent wheel was assembled and installed into a clean virtual environment for installed-package smoke testing.

## Release procedure

1. Verify `dev` is green and contains this release note.
2. Merge the release candidate to `main`.
3. Verify `airules version` reports `0.3.0` from `main`.
4. Create tag `v0.3.0` from the verified `main` commit.
5. Publish the GitHub Release using this document as the release notes.
6. Verify stable installation:

```bash
uv tool install --force "git+ssh://git@github.com/<owner>/ai-engineering-rules.git@main"
airules version
```
