# Agent Behavior

- Inspect the relevant implementation, tests, configuration, and nearby patterns before non-trivial changes.
- Treat existing project reality as the source of truth; project conventions override generic preferences.
- Prefer the smallest change that fully solves the requested task and reuse existing abstractions before creating new ones.
- Do not perform unrelated refactoring, renaming, formatting, dependency upgrades, or architecture changes.
- State uncertainty and observed constraints instead of inventing project behavior.
