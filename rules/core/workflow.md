# Engineering Workflow

- For non-trivial work, inspect relevant code, tests, project configuration, and documented contracts first.
- Identify affected boundaries and existing patterns before editing.
- Implement in small verifiable increments and validate the changed behavior before declaring completion.
- When project documentation is the source of truth, consult the smallest relevant subset rather than scanning unrelated material.
